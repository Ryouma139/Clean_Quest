## 2. 追加した機能

### 2-1. 掃除カレンダー

| 項目 | 内容 |
|---|---|
| 画面 | 新しいメニュー「▦ カレンダー」（サイドバー・スマホの下部ナビ） |
| 内容 | 月曜始まりのカレンダーに、日ごとの掃除の絵文字とポイントを表示。日付を押すとその日の記録の一覧（時刻・ポイント・画像） |
| 月の集計 | 表示中の月の掃除回数・獲得ポイント・掃除した日数 |
| 操作 | ‹ › で月を移動、「今日」で今月に戻る |
| DB | 既存の `cleaning_logs` を期間指定で読むだけ（変更なし） |
| ファイル | `src/pages/CalendarPage.tsx` |

### 2-2. 掃除用品の画像・アフィリエイトリンク

| 項目 | 内容 |
|---|---|
| 内容 | 掃除用品に商品画像とアフィリエイトリンクを設定できる。画像が無ければ絵文字、リンクが無ければ「商品リンク準備中」 |
| リンク | 新しいタブで開く。「PR」ラベルと「このページはアフィリエイト広告を含みます」の表記（ステマ規制への対応）。`rel="sponsored"` |
| 安全対策 | URL は `https://` のみ登録可（DB の制約＋画面側でも確認） |
| 表示場所 | 掃除用品の画面、ホームの「おすすめ掃除用品」 |
| DB | `cleaning_tools` に `image_url` を追加、`product_url` を `affiliate_url` に名前変更 |

当初は報酬ショップにも画像・リンクを付けましたが、ご要望により掃除用品のみに変更しました。

### 2-3. 報酬ショップ → 「ご褒美を選ぶ」画面

| 項目 | 内容 |
|---|---|
| 流れ | 報酬ショップで「交換する」→ 確認 → ポイントを使う → **交換した報酬の「ご褒美を選ぶ」画面**に移動 |
| ご褒美を選ぶ画面 | 報酬ごとの商品（画像・名前・説明・アフィリエイトリンク）を表示。「すべて／各報酬」の切り替え、「← 報酬ショップに戻る」 |
| サンプル商品 | 各報酬に3件、計18件（画像・リンクは空） |
| メニュー | 報酬ショップの子画面（メニューには出さない） |
| DB | 新しいテーブル `reward_items`（`reward_id` で `rewards` に紐づく） |
| ファイル | `src/pages/RewardItemsPage.tsx`、`src/components/ProductCard.tsx`（掃除用品と共通の商品カード） |

### 2-4. 管理画面

| 項目 | 内容 |
|---|---|
| 使える人 | `app_admins` テーブルに登録されたユーザーだけ（SQL で登録。アプリからは登録できない） |
| 開き方 | サイドバーの「⚙ 管理画面」、またはマイページの「⚙ 管理画面」ボタン（管理者にだけ表示） |
| タブ | 掃除用品／ポイント枠（報酬）／ご褒美商品／ユーザー |
| 掃除用品・ポイント枠・ご褒美商品 | 追加・編集・削除、公開／非公開の切り替え、表示順 |
| ポイントごとの登録 | ポイント枠はポイントの低い順に表示。ご褒美商品は「500 pt ・ 🍫 スイーツ」のようにポイント枠を選んで登録。各枠に「＋ この枠に商品を追加」 |
| 状態の表示 | 「非公開」「画像なし」「リンク未設定」のバッジ |
| 権限の確認 | 画面だけでなく DB 側（RLS の `is_admin()`）でも確認。管理者以外は書き込めない |
| ファイル | `src/pages/AdminPage.tsx`、`src/components/admin/AdminForm.tsx`、`src/api/admin.ts` |

管理者の登録方法（SQL Editor で実行）：

```sql
insert into public.app_admins (user_id)
select id from auth.users where email = 'メールアドレス';
```

### 2-5. ミッションの掃除前・掃除後の画像

| 項目 | 内容 |
|---|---|
| 流れ | 「掃除を開始する」→ ① 掃除前の画像 → ② チェックリスト → ③ 掃除後の画像 → 完了 |
| 追加方法 | 画像ファイルを選択、またはドラッグ＆ドロップ（カメラは起動しない）。画像は任意 |
| 縮小 | アップロード前に長辺 1600px の JPEG に縮小（スマホ写真の向きも補正） |
| 保存先 | Storage の非公開バケット `cleaning-photos/<ユーザーID>/...`。本人しか見られない |
| 後片付け | 変更・削除・中断したときは、アップロード済みの画像も Storage から削除 |
| 見る場所 | カレンダーで日付を押すと、記録の下に「掃除前／掃除後」を並べて表示 |
| 安全対策 | サーバー側で「自分のフォルダの画像か」を確認してから記録に紐づける |
| ファイル | `src/components/modals/MissionModal.tsx`、`src/components/PhotoPicker.tsx`、`src/utils/image.ts` |

当初はカメラで撮影する形でしたが、ご要望により画像ファイルを追加する形に変更しました。

### 2-6. ランキング

| ランキング | 並び順 |
|---|---|
| 月間ポイント | 今月獲得したポイントの多い順（交換で使っても減らない。毎月1日にリセット） |
| レベル | 累計獲得ポイントの多い順（＝レベルの高い順） |
| 総合 | 月間の順位＋レベルの順位が小さい順（同点は累計ポイントが多い方が上） |

| 項目 | 内容 |
|---|---|
| 画面 | サイドバーの「♛ ランキング」。自分の順位（3つ）、上位50位、自分が圏外なら一番下に自分の行 |
| ホーム | 「あなたの順位」カード（スマホではここからランキングへ） |
| 他のユーザーの表示 | ニックネーム・アバター・レベル・ポイント・順位のみ。メールアドレスやユーザーIDは返さない |
| DB | 関数 `get_rankings(p_limit)`（全員分を集計して必要な項目だけ返す） |
| ファイル | `src/pages/RankingPage.tsx`、`src/components/RankingSummaryCard.tsx` |

### 2-7. ユーザー管理（ユーザー削除）

| 項目 | 内容 |
|---|---|
| 一覧 | ニックネーム、メールアドレス、登録日時、最終ログイン、記録数、累計ポイント、「あなた／管理者／メール未確認」バッジ、検索 |
| 削除の確認 | 削除されるデータの内容を表示し、**そのユーザーのメールアドレスの入力**で確認 |
| 一緒に削除されるもの | プロフィール、掃除箇所、掃除の記録（ポイント）、交換記録、バッジ、管理者の登録（DB の `on delete cascade`）、Storage の画像（アプリが先に削除） |
| 制限 | 管理者のみ。自分自身は削除できない（画面とサーバーの両方で拒否） |
| DB | 関数 `admin_list_users()`、`admin_delete_user(p_user_id)`、Storage の管理者用ポリシー |
| ファイル | `src/components/admin/AdminUsers.tsx`、`src/api/admin.ts` |

## 3. 修正した不具合・見た目

| 内容 | 原因 | 修正 |
|---|---|---|
| 確認リンクのエラーが画面に出ない | Supabase の起動処理が、エラーを読む前に URL から消していた | Supabase のクライアントを作る前にエラーを読み取るよう変更（`src/lib/supabase.ts`）。期限切れリンクの状態を再現して表示を確認済み |
| 商品画像が枠からはみ出して文字に重なる | 画像の高さが枠に固定されていなかった | 画像を枠内に固定し、はみ出しを非表示に |
| 商品画像が大きすぎる | — | 枠の 70%（スマホ 75%）まで縮小し、全体が見えるよう表示（切り取らない）。背景は白 |
| ホームの「おすすめ掃除用品」の画像がはみ出す | 同上（ブラウザに古いスタイルが残っていた可能性もあり） | 72px の枠に固定し、画像は 85% まで |
| 商品カードのボタンの位置がそろわない | 説明文の長さの違い | ボタンをカードの下端にそろえ、商品名は2行まで |
| 報酬ショップの並び順がばらばら | `sort_order` 順だった | 必要ポイントの低い順に変更 |
| ホームの挨拶が常に「おはようございます」 | 固定の文言だった | 画面を開いた時刻で切り替え：0:00〜11:59「おはようございます」、12:00〜16:59「こんにちは」、17:00〜23:59「こんばんは」（`src/utils/format.ts` の `greetingFor`） |
