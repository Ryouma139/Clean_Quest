- 日付の区切りはすべて **日本時間（Asia/Tokyo）**

画面の切り替えは URL ではなくアプリ内の状態（`page`）で行います。ブラウザの戻るボタンやURLの直接指定には対応していません。

```
起動
 ├─ 環境変数が未設定 ─────────→ 設定エラー表示
 ├─ セッション確認中 ─────────→ 「読み込み中…」
 ├─ 未ログイン ─────────────→ ログイン / 新規登録
 └─ ログイン済み
      ├─ データ読み込み中 ────→ 「読み込み中…」
      ├─ 読み込み失敗 ──────→ エラー表示（再読み込み / ログアウト）
      └─ 成功 ──────────→ ホーム ⇄ 各画面（サイドバー / モバイルナビ）
```

## 1. 共通仕様

### 1-1. 起動時の処理（[App.tsx](../src/App.tsx) / [AppContext.tsx](../src/state/AppContext.tsx)）

| 順番 | 処理 | 失敗時 |
|---|---|---|
| 1 | `.env.local` の `VITE_SUPABASE_URL` / `VITE_SUPABASE_ANON_KEY` を確認 | 設定方法の案内を表示 |
| 2 | `supabase.auth.getSession()` で保存済みのログイン状態を復元 | 未ログイン扱い |
| 3 | マスタデータとユーザーデータを並列で取得 | 「再読み込み」「ログアウト」ボタン付きのエラー表示 |

**ログイン後に読み込むデータ**（[api/cleanQuest.ts](../src/api/cleanQuest.ts)）

| 区分 | 取得元 | 条件・並び順 |
|---|---|---|
| マスタ | `missions` | `is_active = true`（RLS）、`sort_order` 順 |
| マスタ | `rewards` | 同上 |
| マスタ | `cleaning_tools` | 同上 |
| マスタ | `badges` | `sort_order` 順 |
| マスタ | `challenges` | 有効なもの1件 |
| ユーザー | `profiles` | 自分の行 |
| ユーザー | `cleaning_task_status`（ビュー） | 自分の行、`sort_order` → `created_at` 順、論理削除済みは除外 |
| ユーザー | `cleaning_logs` | 自分の行、新しい順に最大50件 |
| ユーザー | `user_stats`（ビュー） | 自分の行 |
| ユーザー | `user_badges` | 自分の行 |

### 1-2. 書き込み後の処理
- 書き込み（RPC・INSERT）が成功すると、**ユーザーデータを全部取り直して**画面に反映します。マスタは取り直しません。
- 処理中に別の書き込み操作をしても無視します（二重送信の防止）。
- 失敗したときは、日本語のエラーメッセージをトーストで表示します（[11章](#11-エラーメッセージ一覧)）。

## 2. ログイン / 新規登録

**ファイル**：[AuthPage.tsx](../src/pages/AuthPage.tsx)、[AuthProvider.tsx](../src/auth/AuthProvider.tsx)
**目的**：アカウントを作成し、ログインする。

### 2-1. 画面構成
- ロゴ、キャッチコピー
- タブ：「ログイン」／「新規登録」（切り替えるとメッセージは消える）
- 入力フォーム、エラー／お知らせの表示欄、送信ボタン

### 2-2. 入力項目

| 項目 | ログイン | 新規登録 | 入力チェック（画面側） |
|---|---|---|---|
| ニックネーム | — | ○ | 必須、最大30文字 |
| メールアドレス | ○ | ○ | 必須（形式チェックは Supabase 側） |
| パスワード | ○ | ○ | 6文字以上 |

メールアドレスとパスワードが空のあいだは、送信ボタンを押せません。送信中は「送信中…」と表示し、ボタンを無効にします。

### 2-3. 使用する DB / API

| 操作 | 呼び出し | DB への影響 |
|---|---|---|
| ログイン | `supabase.auth.signInWithPassword` | なし |
| 新規登録 | `supabase.auth.signUp`（`options.data.display_name` にニックネーム、`emailRedirectTo` にアプリのURL） | `auth.users` に追加 → トリガー `on_auth_user_created` が動く |
| ログアウト | `supabase.auth.signOut` | なし |

**新規登録時にトリガーで作られるデータ**（`handle_new_user`）
1. `profiles` に1行追加。`display_name` はニックネーム（前後の空白を除き最大30文字、空なら「そうじねこ」）、`avatar` は 🐱
2. `default_tasks` の全件（5件）を `cleaning_tasks` にコピー

### 2-4. 仕様
- Supabase の「Confirm email」が有効な場合、登録直後はログインしません。「（メールアドレス）に確認メールを送りました」と表示してログインタブに戻り、パスワード欄を空にします。メールのリンクを開くと、ログインした状態でアプリに戻ります。
- 「Confirm email」が無効な場合は、登録と同時にログインしてホームを表示します。
- 登録済みのメールアドレスで登録しようとすると、「このメールアドレスは登録済みです」と表示します。Supabase は登録済みでもエラーを返さず `identities` が空のユーザーを返すため、それで判定しています。
- ログイン状態はブラウザに保存されます。次回からは自動でログインします。
- 別のユーザーでログインし直すと、画面の状態はすべて作り直されます。

## 3. ホーム

**ファイル**：[HomePage.tsx](../src/pages/HomePage.tsx)、[MissionModal.tsx](../src/components/modals/MissionModal.tsx)
**目的**：今日やる掃除を1つ提案し、現在の状況をひと目で確認できるようにする。

### 3-1. 画面構成と表示データ

| エリア | 表示内容 | データ |
|---|---|---|
| 挨拶 | 「（ニックネーム）さん、おはようございます！」 | `profiles.display_name` |
| 日付 | 例：2026年11月15日(日) | 端末の現在日時 |
| 統計カード：保有ポイント | 例：1,250 pt | `user_stats.points_balance` |
| 統計カード：現在のレベル | Lv.X ／ 次のレベルまで X pt | `user_stats.level`, `points_to_next_level` |
| 統計カード：今週の掃除 | X 回（0回なら「今週の1回目をやってみよう」） | `user_stats.weekly_count` |
| クエストカード | 画像、名前、説明、所要時間、獲得報酬 | `missions` の1件 |
| 今日の掃除状況 | 完了数 / 全体数、進捗バー、先頭4件の状態 | `cleaning_task_status.done_today` |
| おすすめ掃除用品 | 商品画像（無ければ絵文字）、名前、説明、「PR 商品を見る →」リンク（無ければ「商品リンク準備中」） | `cleaning_tools` の先頭1件（`sort_order` 最小）の `image_url`, `affiliate_url` |
| 今週のチャレンジ | タイトル、ボーナス、現在 X / 目標 日、進捗バー | `challenges` の1件、`user_stats.streak_days` |

マスタにデータが無い場合：
- ミッションが0件 → クエストカードの代わりに「現在ミッションはありません。」
- 掃除用品が0件 → おすすめカードを表示しない
- チャレンジが0件 → チャレンジカードを表示しない

### 3-2. クエストカードの仕様
- 表示するミッションは、ログイン時に**ランダムに1件**選びます。
- 「⟳ 別のミッション」を押すと、**今と違うミッション**をランダムに選び、「新しいミッションを選びました！」と表示します。
- 画像（`missions.image_url`）が無い、または読み込みに失敗した場合は、代わりに絵文字（`missions.emoji`）を大きく表示します。

### 3-3. ミッションの実行（ダイアログ）

| 手順 | 画面の動き |
|---|---|
| 1 | 「▶ 掃除を開始する」を押すとダイアログが開く。チェックは毎回リセット |
| 2 | タイトル、説明（目安時間つき）、チェックリスト（`missions.steps`）を表示 |
| 3 | すべてにチェックを入れると「掃除を完了する」が押せるようになる |
| 4 | 押すと `rpc('complete_mission', { p_mission_id })` を呼ぶ |
| 5 | 成功するとダイアログを閉じ、「ミッション達成！ +X pt 🎉」と表示 |

「中断する」ボタンか背景を押すと、記録せずに閉じます。

**`complete_mission` の処理（サーバー側）**

| 確認・処理 | 内容 |
|---|---|
| ログイン確認 | 未ログインならエラー |
| ミッションの存在 | 無いか無効ならエラー |
| 1日1回の制限 | 同じミッションを今日すでに完了していればエラー（「今日はもう完了しています」） |
| 掃除箇所との連動 | `missions.task_template_key` と同じ `template_key` を持つ自分の掃除箇所を探す |
| 記録 | `cleaning_logs` に1行追加：`name` はミッション名から「！」を除いたもの、`points` はミッションのポイント、`task_id` は連動先（無ければ空）、`mission_id` はミッションID |

連動先の掃除箇所がある場合、その掃除箇所も「今日完了」になります（例：「洗面台を磨こう！」を完了すると、掃除管理の「洗面台」も完了になる）。

## 4. 掃除管理

**ファイル**：[CleaningPage.tsx](../src/pages/CleaningPage.tsx)、[AddTaskModal.tsx](../src/components/modals/AddTaskModal.tsx)
**目的**：自分の掃除箇所を管理し、日々の掃除を記録する。

### 4-1. 画面構成と表示データ

| エリア | 表示内容 | データ |
|---|---|---|
| 絞り込みボタン | すべて／キッチン／水回り／居室 | 固定（DB の enum `cleaning_area` と同じ） |
| 登録ボタン | 「＋ 掃除箇所を登録」 | — |
| 掃除箇所の一覧 | 絵文字、「カテゴリー / 名前」、「頻度 ・ X pt」、状態バッジ、操作ボタン | `cleaning_task_status` |

- 状態バッジ：今日完了していれば「✓ 完了」（緑）、未完了なら「未実施」（黄）
- 操作ボタン：未完了なら「完了」、完了済みなら「戻す」
- 絞り込みは画面上だけで行います（DB に再問い合わせしない）
- 0件のときは「掃除箇所がありません。「＋ 掃除箇所を登録」から追加しましょう。」と表示

### 4-2. 完了 / 戻す

| 操作 | 呼び出し | サーバー側の処理 | 成功時の表示 |
|---|---|---|---|
| 完了 | `rpc('complete_task', { p_task_id })` | 自分の掃除箇所か確認 → 今日すでに記録があればエラー → `cleaning_logs` に追加（名前とポイントは掃除箇所の値） | 「掃除を記録しました！ +X pt」 |
| 戻す | `rpc('undo_task', { p_task_id })` | その掃除箇所の、今日の最新の記録を1件削除 | 「未完了に戻しました」 |

「戻す」で記録を削除するので、ポイントも元に戻ります。ポイントは記録から計算しているためです。ミッション経由の記録も、掃除箇所と連動していれば「戻す」で取り消されます。

### 4-3. 掃除箇所の登録（ダイアログ）

| 項目 | 入力方法 | 初期値 | 入力チェック |
|---|---|---|---|
| 掃除箇所名 | テキスト | 空 | 必須、最大50文字（DB でも 1〜50 文字に制限） |
| カテゴリー | 選択 | キッチン | キッチン／水回り／居室 |
| 掃除頻度 | 選択 | 毎日 | 毎日／週1回／週2回／月1回 |
| 獲得ポイント | 数値 | 30 | 1〜1000。範囲外は画面側で丸め、数値でなければ 30（DB でも 1〜1000 に制限） |

- **使用する DB**：`cleaning_tasks` に INSERT します。`user_id` は DB の初期値 `auth.uid()`、絵文字は 🧹 固定です。
- **成功時**：ダイアログを閉じ、「掃除箇所を登録しました」と表示します。入力欄の名前を空にします（他の項目は前回の値のまま）。
- **未入力時**：名前が空なら「掃除箇所名を入力してください」と表示します。
- **送信中**：「登録中…」と表示し、ボタンを無効にします。

## 5. 掃除カレンダー

**ファイル**：[CalendarPage.tsx](../src/pages/CalendarPage.tsx)
**目的**：いつ、どこを掃除したかを、日付ごとにカレンダーで振り返る。

### 5-1. 画面構成と表示データ

| エリア | 表示内容 | データ |
|---|---|---|
| 月の統計：掃除回数 | 「（月）月の掃除回数」X 回 | 表示中の月の `cleaning_logs` の件数 |
| 月の統計：獲得ポイント | 「（月）月の獲得ポイント」X pt | 表示中の月の `cleaning_logs.points` の合計 |
| 月の統計：掃除した日数 | 「（月）月に掃除した日数」X 日 | 表示中の月で記録がある日の数 |
| 月の切り替え | ‹ 2026年11月 › ／「今日」ボタン | — |
| カレンダー | 月曜始まり。日付、その日の掃除の絵文字（最大3つ＋残り件数）、獲得ポイント合計 | `cleaning_logs`（表示中の週すべて） |
| 日別の記録 | 選んだ日の日付、合計ポイント、記録の一覧（絵文字、名前、時刻、ミッション経由かどうか、ポイント） | 同上 |

**使用する DB**：`cleaning_logs` を読むだけです。テーブルの追加や変更はありません。

```
supabase.from("cleaning_logs").select("*")
  .gte("completed_at", 表示の先頭日 0:00)
  .lt("completed_at", 表示の最終日の翌日 0:00)
  .order("completed_at")
```

RLS により、自分の記録だけが返ります。インデックス `cleaning_logs_user_time_idx`（`user_id, completed_at`）が使われます。

### 5-2. カレンダーの表示ルール

| 項目 | ルール |
|---|---|
| 週の始まり | 月曜（`user_stats.weekly_count` の「今週」と同じ） |
| 表示範囲 | 月の1日を含む週の月曜から、月末を含む週の日曜まで（4〜6週） |
| 前後の月の日付 | 薄く表示。その日の記録も表示する |
| 今日 | 日付を青い丸で表示 |
| 選択中の日 | 青い枠で表示 |
| 土曜・日曜 | 日付と曜日を青・赤で表示 |
| マスの色 | その日の記録数で緑を濃くする（1件／2件／3件以上の3段階） |
| 絵文字 | 掃除箇所の絵文字 → ミッションの絵文字 → 🧹 の順に探す |
| 日付の区切り | 端末の時刻で判定（日本時間を想定） |

### 5-3. 操作

| 操作 | 動き |
|---|---|
| 日付を押す | その日の記録を右側（スマホでは下）に表示。前後の月の日付を押すと、その月に移動する |
| ‹ / › | 前の月／次の月へ移動。移動先が今月なら今日を、それ以外なら1日を選ぶ |
| 今日 | 今月に戻り、今日を選ぶ |

- **開いたとき**：今月を表示し、今日を選んだ状態にします。
- **データの更新**：月を切り替えるたびに、その期間の記録を取得します。ほかの画面で掃除を記録・取り消しした場合も、取り直して反映します。
- **読み込み中**：カレンダーの下に「読み込み中…」と表示します。
- **失敗時**：エラーメッセージをカレンダーの下とトーストに表示します。
- **記録が無い日**：「この日の掃除記録はありません。」と表示します。

## 7. 報酬ショップ

**ファイル**：[RewardsPage.tsx](../src/pages/RewardsPage.tsx)
**目的**：貯めたポイントをご褒美と交換し、その報酬の商品リンク一覧（[7-3. ご褒美を選ぶ](#7-3-ご褒美を選ぶ画面)）へ進む。

### 7-1. 画面構成と表示データ

| エリア | 表示内容 | データ |
|---|---|---|
| ポイント表示 | YOUR POINTS ／ X pt | `user_stats.points_balance` |
| 報酬カード | 絵文字、名前、説明、必要ポイント、「交換する」ボタン | `rewards` |

報酬には画像やリンクを持たせません。商品の画像とアフィリエイトリンクは掃除用品だけが持ちます。

### 7-2. 交換の流れ

| 手順 | 内容 |
|---|---|
| 1 | ポイントが足りない報酬は、ボタンを押せない状態で表示 |
| 2 | 「交換する」を押すと、確認ダイアログ「（名前）を X ptで交換しますか？ 交換後、商品の一覧に移動します。」を表示 |
| 3 | OK を押すと `rpc('redeem_reward', { p_reward_id })` を呼ぶ |
| 4 | 成功すると「（名前）と交換しました！ ご褒美の商品を選びましょう」と表示し、**その報酬の「ご褒美を選ぶ」画面に移動する** |
| — | キャンセルした場合や、交換に失敗した場合は移動しない |

**`redeem_reward` の処理（サーバー側）**
1. ログインと報酬の存在を確認
2. 同じユーザーの交換処理を1件ずつ順番に実行する（同時に押しても残高を超えて交換できないようにするため）
3. 残高（`user_stats.points_balance`）が足りなければエラー（「ポイントが足りません」）
4. `reward_redemptions` に1行追加：報酬ID、記録時点の名前、ポイント

交換を取り消す機能はありません。

**目的**：交換した報酬に合ったご褒美の商品を、アフィリエイトリンクから選ぶ。

## 10. 計算ルール

DB のビューで計算しており、画面側では計算していません。

| 項目 | 計算方法 | 定義場所 |
|---|---|---|
| 保有ポイント | 獲得ポイントの合計（`cleaning_logs`） − 交換ポイントの合計（`reward_redemptions`） | `user_stats.points_balance` |
| 累計獲得ポイント | `cleaning_logs.points` の合計 | `user_stats.total_earned` |
| 累計掃除回数 | `cleaning_logs` の件数 | `user_stats.total_count` |
| 今週の掃除 | 今週月曜 0:00 以降の `cleaning_logs` の件数 | `user_stats.weekly_count` |
| レベル | 累計獲得ポイント ÷ 500（切り捨て）＋ 1 | `user_stats.level` |
| 次のレベルまで | 500 − （累計獲得ポイント ÷ 500 の余り） | `user_stats.points_to_next_level` |
| 連続達成日数 | 記録がある日が途切れずに続いた日数。最後の記録が今日か昨日の場合だけ数え、それより前なら 0 | `user_streaks.streak_days` |
| 今日完了したか | その掃除箇所の最新の記録が今日の日付か | `cleaning_task_status.done_today` |

レベルの計算式は暫定です。500 を変える場合は、DB のビューと画面側の定数 `LEVEL_STEP`（[types.ts](../src/types.ts)）を両方直してください。
